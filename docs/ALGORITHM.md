# 推荐算法详解

## 设计目标

从 160+ 道麦当劳餐品中，根据用户画像（年龄段、职业、口味、心情、健康关注、时段），返回 Top N 最匹配的餐品，并附带**可解释的推荐理由**。

## 核心思想：多维加权打分

每个维度独立计算得分，最终总分 = 各维度得分之和。餐品按总分降序排列，再加多样性约束后取 Top N。

## 维度与权重

| 维度 | 权重上限 | 说明 |
| --- | --- | --- |
| 年龄段适配 (ageFit) | 25 | 餐品是否明确标注该年龄段适配 |
| 心情匹配 (mood) | 24 | moodFit 与用户心情 / 自由文本解析结果的交集数量 |
| 健康需求 (health) | 25 | 营养标签命中数 × 10（上限 25） |
| 口味对味 (flavor) | 20 | 口味标签命中数 × 8（上限 20） |
| 职业场景 (occupation) | 18 | occupationFit 命中 |
| 时段契合 (mealTime) | 12 | 餐品 mealTime 等于用户时段（auto 时根据当前小时推断） |
| 特殊群体软约束 | 8-12 | 老人/孕妇/儿童 低钠 (<500mg)；健身 高蛋白低脂 (蛋白≥20g 且 脂肪≤15g) |

## 自由文本心情解析

`moodText` 字段支持自然语言输入，算法会扫描 30+ 中文情绪关键词：

```ts
"今天加班到深夜，想喝点提神的不太甜的" 
→ 命中：累/疲惫 → warmUp/comfort/energize
       加班 → focus/energize/comfort
       提神 → focus/energize
```

关键词映射表见 `backend/src/utils/tagMaps.ts` 的 `MOOD_KEYWORDS`。

## 时段推断

```ts
05:00-10:00 → breakfast
10:00-14:00 → lunch
14:00-17:00 → snack
17:00-21:00 → dinner
其他        → snack
```

用户可手动覆盖 `mealTime` 字段。

## 隐式偏好

用户的**职业**和**年龄段**会激活隐式口味/营养偏好，例如：
- `programmer` → 偏好咖啡、含咖啡因
- `fitness` → 偏好高蛋白、低脂、低卡
- `pregnant` → 偏好清淡、高钙、低钠
- `senior` → 偏好清淡、软糯、低钠、高钙

这些隐式偏好会**叠加**到用户显式选择之上，进一步细化口味标签集。

## 多样性约束

避免 Top N 中同一 category 出现超过 2 次，确保推荐组合的多样性。

实现：按分数降序遍历，遇到已出现 ≥2 次的 category 直接跳过。

## 推荐理由生成

每条推荐会从命中的维度里抽取人类可读的理由，例如：

```
✅ 年龄段适配
✅ 职业场景对位：程序员
✅ 口味对味：冰、咖啡
✅ 心情匹配：需要专注
✅ 健康需求达标：含咖啡因、低卡
✅ 低卡友好
```

## 未来可优化方向

1. **协同过滤**：记录用户历史推荐反馈，反向调整权重
2. **A/B 测试**：上线后埋点对比不同算法的转化率
3. **天气/季节维度**：从 MCP 调用天气接口，动态加入"夏天推荐冰饮"
4. **大模型润色**：把规则打分的 Top 5 喂给大模型生成更生动的推荐理由文案
